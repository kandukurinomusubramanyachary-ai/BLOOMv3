# The requested 20 features

| # | Feature | Implementation |
|---|---|---|
| 1 | Dark mode toggle | Header control, OS default, remembered preference, both themes designed |
| 2 | Cookie banner | Essential-only and optional campaign attribution choices; settings can be reopened |
| 3 | Site search | Local content index including the full original story; Ctrl/Cmd K shortcut |
| 4 | Back to top | Floating control appears after scrolling and returns focus to the header |
| 5 | Mobile menus | Responsive navigation, keyboard loop, Escape and close-on-navigation |
| 6 | Loading animations | Nonblocking indicator for real font/image loading; reduced-motion behavior |
| 7 | Hover states | Visible feedback for primary actions, navigation, results and floating controls |
| 8 | Scroll progress | Top bar follows actual document progress |
| 9 | Copy buttons | Doctor note and feedback draft copying with success/failure feedback |
| 10 | Print stylesheet | Doctor note and story; excludes navigation, dialogs and floating controls |
| 11 | Sticky headers | Persistent navigation with anchor offset |
| 12 | Skip to content | First keyboard stop, visible focus and main-content target |
| 13 | Password visibility | Actual app’s shared AuthField in src/screens/AuthScreen.js; covers login, signup and confirmation. No account form is invented on the marketing site. |
| 14 | UTM tracking | Standard UTM fields retained for 30 days only after campaign consent and passed to existing signup; rejecting clears them. No third-party analytics. |
| 15 | Form success | Sample check-in completion and prepared feedback draft states |
| 16 | Form errors | Missing energy selection and invalid product feedback receive real validation |
| 17 | Confirmation modals | Reset confirmation, cancellation, Escape and focus restoration |
| 18 | Last updated date | Visible, machine-readable October 24, 2026 date |
| 19 | Expandable FAQ | Native keyboard-accessible details and summary |
| 20 | Floating contact | Validated product feedback dialog, copy and GitHub draft link; nothing automatically posted |

Feedback uses the existing BLOOMv3 repository’s enabled GitHub Issues. No private contact information is published. Actual waitlist registration remains on the original Bloom website.
